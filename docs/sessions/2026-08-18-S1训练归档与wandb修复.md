## 方法与决策

### wandb 集成修复

**问题诊断**:
1. 用 Agent 工具排查，发现 wandb run `qnue251x` 数据结构: `{history: 0, output_raw: 18627, stats: 1830}` —— 心跳和控制台日志正常，唯独指标缺失
2. 代码审查发现 `SummaryWriter` 在 `wandb.init()` 之前实例化（train_lingbotvla.py:563-565）
3. `sync_tensorboard=True` 工作原理是 monkey-patch `torch.utils.tensorboard.SummaryWriter`，但 patch 发生在 init 时，已创建的实例不受影响

**修复方案**:
- 移除 `sync_tensorboard=True`（根本原因无法绕过：构造顺序依赖）
- 将 `writer = AsyncTBWriter(...)` 移到 `wandb.init()` 之后（防止未来有人重新启用 sync）
- 在现有 TensorBoard logging block 末尾添加显式 `wandb.log()` 调用，批量上报所有指标（1069-1116 行）
- 用 try/except 包裹，确保 wandb 失败不会 crash 训练

**网络配置**:
- 两台训练节点的 `~/.bashrc` 在 `[ -z "$PS1" ] && return` 之后才 export proxy，导致 SSH 启动的非交互 shell 拿不到
- 修改 bashrc 将 proxy 声明移到守卫之前
- 在 `run_train.sh` 中也显式 export（双保险）
- 增加 `WANDB_INIT_TIMEOUT=300` 和 `WANDB__SERVICE_WAIT=300`（两节点都出现过 90s 超时）

## 踩坑

### 1. wandb history 完全空白但 heartbeat 正常

**现象**: wandb run 页面能看到进程在线、GPU 使用率，但 Metrics 标签页空白，API 查询 `run.summary_metrics` 返回空。

**原因**: `sync_tensorboard=True` 依赖 monkey-patch `SummaryWriter.__init__()`，但代码里 writer 在 `wandb.init()` 之前就创建了，patch 时机晚了。patch 后的 `add_scalar()` 调用会被 wandb 拦截并转成 history record，但已存在的实例用的是原始实现，只写 tfevents 不写 wandb。

**怎么绕**: 弃用 `sync_tensorboard`，改用显式 `wandb.log({...}, step=global_step)`。副作用：需要手动镜像所有 TensorBoard 指标到 wandb（本次加了 40+ 个 key）。

### 2. SSH 启动的训练拿不到 proxy

**现象**: 本地 `curl` 测试能通，训练进程 `wandb.init()` 一直 timeout（90s）。

**原因**: `~/.bashrc` 在 `[ -z "$PS1" ] && return` 后面才 export proxy。SSH 启动的非交互 shell 会执行 bashrc，但遇到 `return` 就退出，后面的 export 不执行。

**怎么绕**: 把 proxy export 移到 `return` 之前。同时在 `run_train.sh` 里也显式 export 一遍（防止 bashrc 被其他人改回去）。

### 3. NCCL timeout 误报

**现象**: Stereo 训练跑完 60000 步后，日志显示 checkpoint 已保存，但最后报 NCCL BROADCAST timeout（rank 2, 600s watchdog）。

**原因**: Checkpoint 保存是真的完成了（`global_step_60000/` 目录完整，874 GB），NCCL timeout 发生在训练循环退出后的某个隐式同步点（可能是 FSDP state_dict gather）。不是数据丢失，是清理阶段的协调超时。

**怎么绕**: 已确认 checkpoint 完整就行，这个 timeout 可以忽略。如果后续频繁遇到，可以在 FSDP 配置里调大 `timeout` 参数或在保存完 checkpoint 后显式 `dist.barrier()`。

### 4. Git push 报 "Repository not found"

**现象**: `git push fork main` 返回 `fatal: repository 'https://github.com/bananea20/lingbot-vla-v2.git/' not found`。

**原因**: 用户还没有 fork 上游仓库，remote URL 指向一个不存在的地址。

**怎么绕**: 让用户先在 GitHub 网页上点 Fork 按钮，创建完成后再 push。
